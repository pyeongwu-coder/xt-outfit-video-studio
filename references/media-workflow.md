# 媒体调用与生成编排

在需要分析、生成或上传媒体时读取。本页记录当前工作流；实际参数始终以运行时暴露的 `ai-tool-center` 工具 schema 为准。

## 前置检查

确认 `ai-tool-center` 已连接且至少具备任务需要的媒体工具。若服务器缺失、工具不可用、认证失败或余额不足，保留真实错误并停止相关媒体操作；不要绕到别的外部服务，也不要声称已生成。

## 工具路由

- 本地图片上传：`prepare_image_upload`；执行其返回的上传命令后使用对应 `image_url`。若运行环境提供可直接处理对话图片的方式，按当前 schema 使用。
- 本地视频或大文件：需要公网 URL 或对象键时使用 `direct_upload_media` 或 `prepare_media_upload`。
- 图片分析：`analyze_image`；技术元数据可用 `analyze_media`。
- 视频拆解：公开视频使用 `analyze_video`；本地视频先按 schema 上传，或用 `analyze_media` 读取元数据后再分析可访问 URL。
- 身份锚点、全身补全和服装关键帧：`generate_image`。
- 视频生成：`generate_video`；保存返回的 `job_id`，按工具建议约每 10 秒调用 `get_video_generation`，直到 `succeeded` 或 `failed`。

## 图片顺序合同

提交视频时显式固定参考顺序，并把相同顺序写进提示词：

1. `I1`：9:16 模特身份锚点，也是图片参考模式下的画幅锚点。
2. `I2...`：`G1...Gn` 服装参考；同一单品的多角度紧邻排列。
3. 其后才是经用户确认的场景或造型关键帧。

提示词必须逐项声明职责，例如“图片 1 仅锁定同一人物的脸、肤色表现、发型和身体比例，不继承其服装；图片 2 是 G1 上衣，锁定领口、主色和图案”。不要只写“参考以上图片”。

## 视频参考合同

自定义风格的视频放在 `videos`，只负责动作、机位、节奏和转场。提示词必须明确：忽略参考视频中的人物身份、服装、文字、商标和原声，以 `I1` 和 `G1...Gn` 为准。

若选择参考视频编辑且时长跟随原视频，只在当前 schema 明确支持时使用对应时长设置。否则按用户时长或风格默认时长生成。

## 模型与时长

运行时先检查当前 `generate_video` schema 暴露的模型名和能力。若存在并支持本次输入的 `wan3.0` / Wan 3.0，优先使用它生成视频；只有该模型未暴露、不可用或不支持所需图片/视频参考、时长、比例或分辨率时，才回退到其他符合 schema 的模型，并在交付中标记“Wan 3.0 不可用/未使用”的实际原因。不得凭记忆拼接模型名，也不得声称使用了未在工具返回中确认的 Wan 3.0。

- 不要给最大时长小于目标时长的模型提交 19 秒或 30 秒任务。
- 单次时长上限不足时按完整动作节点分段，不在换装动作中间切段。
- 图片参考模式的比例可能跟随首图，因此 `I1` 应按目标画幅生成。
- 只使用 schema 接受的比例、分辨率、模型名和 URL 类型，不凭记忆拼参数。

## 关键帧策略

出现以下情况时，先生成并确认关键帧，再生成视频：

- 文字数字人首次定稿；
- 头像需要补成全身身份锚点；
- 单张服装图包含多件服饰或背景人物；
- 一段内有多次换装且细节保持要求高；
- 参考视频人物/服装容易污染用户素材。

多套造型可在一次图片批量生成请求中生成多张关键帧。每张都使用相同 `I1` 和对应服装参考，并保持同一机位、场景和人物比例。

## 失败处理

- 上传失败：保留失败文件名和错误，不继续提交缺参考的生成任务。
- 任务 `failed`：报告真实错误，修正明确的参数或素材问题后最多局部重试；不无限轮询或反复付费提交。
- 任务成功但服装或身份未通过：只重做失败片段，并提高关键帧约束或减少单段换装次数。
- 只有获得真实可访问的视频结果后，才能写“视频已生成”。
