# 自定义风格拆解

只在用户选择 `custom-reference` 时读取。

## 目标

把参考视频拆成可迁移的“风格语法”，再用用户的模特和服装重建。参考视频是证据，不是可直接照抄的完整提示词。

## 分析顺序

1. 先确认视频实际可读取。公开视频使用当前可用的视频理解工具；本地视频可先读取技术元数据并按当前 MCP schema 上传或分析。
2. 分开记录“观察事实”和“生成推断”。看不清的台词、服装细节、帧率、镜头或声音写“无法确认”。
3. 按时间轴拆解以下维度：
   - 时长、画幅、镜头数量和平均镜头长度；
   - 景别、机位、焦段观感、运镜与构图；
   - 开头钩子、主体动作、换装触发、转场机制和结尾定格；
   - 卡点节奏、音乐类型、动作音效、对白、字幕和 UI；
   - 场景、光线、色调、材质和真实/卡通程度；
   - 原人物、原服装、原商标、原文案和原声中必须替换的元素；
   - 人脸、身材、服装、道具和背景的连续性风险。

## 自定义风格卡

分析后先用以下短结构让用户确认：

```markdown
风格名称：
观察到的核心机制：
默认时长 / 画幅：
镜头与转场：
模特表演：
服装展示方式：
声音与文字：
将保留：
将替换：原人物 → 用户模特；原服装 → G1...Gn；原品牌/文案/原声 → 不复用
无法确认：
生成风险：
```

只有用户确认该卡，或用户在最初请求中明确要求“按这个视频直接拆解并生成”，才继续。后一种情形仍要记录风格卡，但无需重复等待确认。

## 参考职责

- 参考视频：只提供可迁移的动作、镜头、节奏和转场。
- 模特图：唯一身份锚点，优先级高于参考视频人物。
- 服装图：唯一服装锚点，优先级高于参考视频服装。
- 用户明确的文案、品牌和平台要求：优先于参考视频内容。

生成工具允许视频参考时，可把参考视频作为 `videos` 传入，并在提示词中写清上述职责。若视频参考导致原人物或原服装残留，停止继续复用该视频作为生成参考，改用拆解后的文字镜头语法和用户关键帧重生成。

## 风格扩展

默认只在当前任务中使用拆解结果。只有用户明确要求“保存为新预设”时，才将已确认的风格卡和完整生成模板另存为新的参考文件；不得覆盖现有四个预设，且必须为新风格使用唯一名称。
